# 任务：个人博客 UI 深度视觉优化与设计还原

你现在需要对当前已经实现的「三藏の博客」进行一次专业级 UI/UX 视觉重构。

本次任务不是增加新功能，也不是重新设计一套页面，而是针对当前实现与目标设计效果之间的差距进行系统性修复。

请将本次对话中提供的目标设计图作为唯一视觉基准，将当前网页截图作为待优化对象。

核心目标：

将当前偏窄、偏扁平、信息密度不合理的博客页面，优化成具有高级感、空间感、未来科技感的暗黑系个人博客。

必须保留现有项目的业务功能、文章数据、路由和交互逻辑。

不要为了视觉优化而破坏已有功能。

---

# 第一部分：优先修复整体布局

这是本次优化最重要的任务。

当前页面存在明显的内容区域过窄、右侧空间浪费、布局重心偏左等问题。

请重新检查整体布局容器、Grid、Flex、max-width、width、margin、padding 等 CSS 属性。

## 1. 整体页面布局

桌面端采用三栏布局：

左侧导航：
- 固定宽度：190px。
- 固定定位。
- 高度：100vh。
- 独立背景和右侧分隔线。

中间主内容：
- 自适应宽度。
- 占据页面主要视觉区域。
- 建议宽度：minmax(0, 1fr)。

右侧信息栏：
- 固定宽度：290px。
- 与主内容保持合理间距。
- 展示个人信息、热门标签、近期动态。

整体结构：

Sidebar | Main Content | Right Sidebar

建议：

```css
.app-layout {
  display: grid;
  grid-template-columns: 190px minmax(0, 1fr) 290px;
  gap: 24px;
  width: 100%;
  min-height: 100vh;
  padding: 0 28px 0 0;
}
```

主内容必须充分利用可用屏幕空间。

禁止出现：
- 主内容集中在页面左侧。
- 右侧大面积空白。
- 不合理的 max-width 限制。
- 文章卡片被挤压。
- 个人资料卡片占据主内容区域。
- 过多无意义的留白。

在 1440px、1600px、1920px 屏幕下分别验证布局。

对于较小屏幕，使用响应式断点合理调整三栏结构，不允许直接缩小整个页面。

---

# 第二部分：重新建立视觉设计系统

## 2. 色彩体系

整体保持暗黑科技风，禁止蓝紫色作为主色。

建议：

```css
:root {
  --bg-primary: #060A0F;
  --bg-secondary: #0A1118;
  --bg-card: #101923;
  --bg-card-hover: #15232C;

  --accent-primary: #16D8C5;
  --accent-secondary: #28A99A;

  --text-primary: #E8F0F2;
  --text-secondary: #9AAAB5;
  --text-muted: #687985;

  --border-primary: rgba(130, 170, 180, 0.18);
  --border-accent: rgba(22, 216, 197, 0.45);

  --glow-accent: rgba(22, 216, 197, 0.12);
}
```

视觉要求：

- 主背景接近纯黑，但不能完全没有层次。
- 卡片使用深石墨色。
- 局部使用青绿色辉光。
- 文字保证清晰可读。
- 使用不同深度的背景色区分内容模块。
- 边框使用低透明度青灰色。
- 不要大面积使用渐变。
- 不要让所有组件都发光。

## 3. 背景重新设计

当前背景网格过于均匀、单调。

改为多层次科技空间背景：

第一层：纯暗色基础背景。

第二层：低透明度科技网格，网格间距建议 48px。

第三层：局部青绿色径向辉光。

第四层：少量星空粒子和细微流星。

第五层：Hero 区域独立的空间场景图片。

背景必须有空间纵深感。

注意：
- 网格不能影响内容阅读。
- 粒子不能过密。
- 背景不能抢夺文章卡片的视觉注意力。
- 页面滚动时背景保持稳定，不要出现明显断层。

---

# 第三部分：重新设计 Hero 主视觉

Hero 必须成为整个首页的第一视觉焦点。

当前 Hero 区域过于简单，需要重新调整。

建议：

- 高度：300～360px。
- 宽度：主内容区域的全部宽度。
- 使用横向科技场景图片。
- 圆角：14～18px。
- 边框：低透明度青绿色。

背景主题：

深邃宇宙、巨大行星、未来城市、科技空间站、探索者。

文字布局：

顶部小标签：

FRONTEND ENGINEER · CREATIVE TECHNOLOGIST

主标题：

在代码与宇宙之间

第二行：

记录每一次跃迁

副标题：

在代码与宇宙之间，记录工程实践的每一次跃迁。

按钮：

开始阅读
关于我

设计要求：

- 主标题 42～52px。
- 第二行采用青绿色强调。
- 文字不能过小。
- 主标题与背景具有明显对比。
- 按钮有清晰的视觉层级。
- Hero 右侧保留足够的背景主体视觉。
- 不要把 Hero 做成普通文章卡片。

---

# 第四部分：重新设计文章展示区域

## 4. 最新文章

当前文章卡片尺寸偏小，整体阅读体验不佳。

采用三列 Grid 布局：

```css
.article-grid {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 16px;
}
```

卡片规范：

- 卡片背景：#101923。
- 圆角：12px。
- 边框：1px solid var(--border-primary)。
- 封面比例：16:9。
- 封面高度：约 150px。
- 卡片内容 Padding：16px。
- 标题字号：16～18px。
- 摘要字号：13～14px。
- 元数据字号：11～12px。

每张卡片应包含：

1. 封面图。
2. 分类标签。
3. 文章标题。
4. 文章摘要。
5. 发布时间。
6. 阅读量。
7. 阅读时间。

文章封面不能全部使用简单的网格背景。

根据文章类型准备不同图片：

- 网络安全：数字盾牌、安全终端。
- Kubernetes：容器集群、云原生架构。
- AI：芯片、神经网络。
- 前端开发：代码编辑器、数字界面。
- Canvas：几何图形、动态粒子。

确保图片具有真实的视觉内容。

## 5. 精选推荐

使用横向三列卡片或大尺寸横幅。

不要重复展示完全相同的文章内容。

每个推荐模块具有独立的视觉设计。

---

# 第五部分：调整个人信息区域

当前个人信息卡片的位置和比例不合理。

将其放入右侧独立信息栏。

右侧依次展示：

1. 个人资料卡。
2. 热门标签。
3. 近期动态。
4. 阅读排行榜。

个人资料卡：

- 头像尺寸：88～100px。
- 头像外围使用青绿色圆环。
- 博客名称和简介。
- 文章数量、总阅读量、建站时间。
- 社交媒体图标。

卡片不能过高，也不能占据过多空间。

热门标签：
- 胶囊样式。
- 不同标签之间保持合理间距。
- Hover 时背景渐亮。
- 选中状态使用青绿色。

近期动态：
- 垂直时间轴。
- 时间、事件名称、事件摘要。
- 使用青绿色节点和细线。

---

# 第六部分：加强卡片视觉层次

所有卡片统一采用设计系统。

但不能让所有卡片完全相同。

建立三个层次：

L1：页面基础背景。

L2：普通内容卡片。

L3：重点交互卡片。

重点卡片可以使用：
- 轻微玻璃拟态。
- 青绿色边框。
- 柔和外部阴影。
- 局部渐变。
- 背景微弱纹理。

Hover 效果：

- translateY(-4px)。
- 边框亮度增强。
- 图片 scale(1.04)。
- 阴影逐渐增强。
- 标题颜色平滑变化。

动画持续 200～300ms。

不要让每个卡片都产生明显的 3D 倾斜。

---

# 第七部分：字体和排版重构

当前页面字体过小，视觉层级不清晰。

统一字体规范：

| 元素 | 字号 |
|---|---|
| Hero 主标题 | 42～52px |
| 页面模块标题 | 22～24px |
| 文章标题 | 16～18px |
| 正文摘要 | 13～14px |
| 普通说明 | 13px |
| 元数据 | 11～12px |
| 标签 | 11～12px |

要求：

- 中文优先使用现代无衬线字体。
- 标题使用较高字重。
- 正文提高行高。
- 文章标题最多显示两行。
- 摘要最多显示三行。
- 元数据不能抢夺标题的注意力。
- 所有模块具有统一的垂直间距。

---

# 第八部分：交互动画视觉升级

保留已有交互动画，并针对视觉质量进行调整。

1. Hero 背景具有轻微视差。
2. 页面模块依次淡入。
3. 文章卡片悬浮时产生轻微上浮。
4. 图片 Hover 时缓慢缩放。
5. Sidebar 激活状态平滑切换。
6. 标签 Hover 时出现青绿色反馈。
7. 搜索框 Focus 时出现柔和辉光。
8. 页面切换采用 250～350ms 过渡。
9. 个人头像外环缓慢旋转。
10. 背景粒子保持低频、低亮度运动。

所有动效必须克制。

---

# 第九部分：严格禁止的设计问题

请特别注意以下事项：

1. 禁止大面积蓝紫色。
2. 禁止把页面做成普通后台管理系统。
3. 禁止主内容区域过窄。
4. 禁止右侧出现无意义的大面积空白。
5. 禁止文章卡片过小。
6. 禁止字体过小。
7. 禁止所有卡片采用相同的纯色背景。
8. 禁止背景网格过于明显。
9. 禁止所有组件都使用霓虹发光。
10. 禁止使用大量无意义的装饰线条。
11. 禁止把个人信息卡放在文章列表左侧。
12. 禁止使用单一图片作为整个页面背景。
13. 禁止通过缩放整个页面来适配不同屏幕。
14. 禁止只修改颜色而不调整布局。
15. 禁止破坏现有文章、路由和搜索功能。

# 第十部分：实际开发与视觉验收

请严格按照以下顺序执行：

第一步：检查当前项目结构。

识别：
- 页面组件。
- 公共布局组件。
- CSS 文件。
- Tailwind 配置。
- 主题变量。
- 路由结构。
- 当前布局宽度和断点。

第二步：分析当前实现与参考图的视觉差距。

第三步：优先修复整体布局。

第四步：调整 Hero、文章卡片、个人资料栏和背景。

第五步：统一字体、间距、边框、圆角和阴影。

第六步：检查动画和交互效果。

第七步：启动项目，使用浏览器进行实际截图。

至少测试：
- 1440×900
- 1600×1000
- 1920×1080
- 390×844

第八步：将实际截图与目标设计图进行对比。

重点检查：
- 三栏布局比例。
- 内容区域宽度。
- Hero 高度和视觉占比。
- 文章卡片尺寸。
- 右侧栏位置。
- 字体层级。
- 背景视觉效果。
- 整体信息密度。

如果差异明显，继续修改，不要在第一次完成后直接结束任务。

最终验收目标：

让页面从当前的窄版、扁平化技术博客，提升为一个具有专业设计感、未来科技感、完整空间层次的暗黑系个人博客。

最重要的是：视觉上必须要有冲击力，而不是仅仅满足功能正确。
